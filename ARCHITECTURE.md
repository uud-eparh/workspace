# OpenLedger — Архитектура и логика

## 1. Общие принципы

- **Мультиарендность**: Система поддерживает неограниченное количество изолированных слоев учета (компаний).
- **Изоляция данных**: Данные каждого слоя изолированы с помощью RLS (Row-Level Security) в PostgreSQL.
- **Аутентификация**: Вход по связке **логин + пароль**. Пароль проверяется против хешей в `membership`.
- **Один логин — одна роль в слое**: Пользователь с одним логином может иметь доступ к нескольким слоям, но в каждом слое у него только одна роль.

---

## 2. Сущности

### 2.1. Пользователь (`global_users`)

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | UUID | Первичный ключ |
| `username` | String(100) | Уникальный логин |
| `email` | String(255) | Уникальный email |
| `full_name` | String(255) | ФИО |
| `department` | String(255) | Отдел |
| `subdivision` | String(255) | Подразделение |
| `role` | Enum | Глобальная роль (`SUPER_ADMIN`, `USER`) |
| `is_active` | Boolean | Активен/заблокирован |

**Важно**: Один человек может иметь несколько логинов.

### 2.2. Слой учета (компания) (`tenants_layers`)

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | UUID | Первичный ключ |
| `name` | String(255) | Название компании (обязательно) |
| `description` | Text | Описание (опционально) |
| `master_key_hash` | String(255) | Мастер-ключ слоя |
| `is_active` | Boolean | Активен |
| `created_by` | UUID | ID пользователя, создавшего слой |

### 2.3. Членство (`membership`)

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | UUID | Первичный ключ |
| `user_id` | UUID | ID пользователя (FK → `global_users.id`) |
| `tenant_id` | UUID | ID слоя (FK → `tenants_layers.id`) |
| `role` | String(50) | Роль внутри слоя: `chief`, `glavbukh`, `kassa`, `sklad` |
| `layer_access_hash` | String(255) | Хеш пароля для входа в этот слой |
| `is_active` | Boolean | Доступ активен |

---

## 3. Роли и права

### 3.1. Глобальные роли (в `global_users.role`)

| Роль | Описание |
|------|----------|
| `SUPER_ADMIN` | Управляет пользователями, видит все роли, может блокировать любого пользователя. **Не имеет доступа к слоям**. |
| `USER` | Обычный пользователь. Может получать доступ к слоям. |

### 3.2. Роли внутри слоя (в `membership.role`)

| Роль | Описание |
|------|----------|
| `chief` | Руководитель слоя. Создает слои, управляет пользователями внутри слоя. |
| `glavbukh` | Главный бухгалтер. Работает с финансами слоя. |
| `kassa` | Кассир. Работает с кассовыми операциями. |
| `sklad` | Кладовщик. Работает со складскими операциями. |

5. Инициализация при первом запуске
Создаются два пользователя:

super_admin / admin123 (глобальная роль: SUPER_ADMIN)

chief / chief123 (глобальная роль: USER)

Слои не создаются!

6. Логика входа
Пользователь вводит логин и пароль.

Система ищет пользователя в global_users по логину.

Если пользователь найден, система ищет все записи membership для этого пользователя.

Система проверяет введенный пароль против layer_access_hash в каждой записи.

Если пароль совпадает с хешем в одной записи → пользователь попадает в соответствующий слой.

Если пароль совпадает с хешами в нескольких записях → ошибка: "Один пароль используется для нескольких слоев".

Если пароль не совпадает ни с одним хешем → ошибка: "Неверный логин или пароль".

Особый случай: Если пользователь имеет глобальную роль SUPER_ADMIN, он входит без слоя (tenant_id = None).

7. Логика дашборда
Суперадминистратор:

Кнопка "👥 Управление пользователями" (/admin/users)

Руководитель (Chief):

Если у пользователя есть доступ к слоям → кнопка "🏢 Управление компаниями" (/tenant/manage)

Если слоев нет → кнопка "➕ Создать компанию" (/tenant/create)

Обычный пользователь:

Если у пользователя есть доступ к слоям → видит свои документы/товары в текущем слое

8. Логика управления компаниями (для Chief)
Создание компании:

Руководитель заполняет форму: Название (обязательно), Описание (опционально).

Система создает слой (tenants_layers).

Система автоматически создает запись в membership для этого руководителя с ролью chief.

Управление пользователями внутри компании:

Руководитель видит список пользователей, у которых есть доступ к его слою.

Может добавить нового пользователя (выбрать существующего или создать нового).

Может назначить роль (glavbukh, kassa, sklad, chief).

Может заблокировать/разблокировать доступ.

Может сбросить пароль.

9. Логика управления пользователями (для Суперадминистратора)
Список пользователей: Видит всех пользователей системы.

Роли: Видит глобальные роли и роли внутри слоев (все слои, где есть пользователь).

Блокировка: Может заблокировать любого пользователя (установить is_active = false).

Создание пользователя: Создает нового пользователя с логином, ФИО, Email, паролем.

10. Ограничения и правила
Один логин — одна роль в слое:

В одном слое у пользователя может быть только одна роль.

Но один логин может иметь доступ к нескольким слоям.

Один пароль — один слой:

Один и тот же пароль не может использоваться для доступа к разным слоям.

При попытке использовать одинаковый пароль для двух слоев — ошибка.

Один человек — несколько логинов:

Один человек может иметь несколько учетных записей (логинов).
