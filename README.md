# 🚀 OpenLedger — Отчёт о проделанной работе

## 📌 Введение

В рамках проекта разработана базовая ERP-система для документооборота с веб-интерфейсом, мультиарендностью («слои учёта») и изолированным доступом по связке **логин–пароль–слой**.

Проект следует принципам, заложенным в спецификации OpenLedger, и полностью воспроизводит требуемый технологический стек и архитектуру.

---

## ✅ Что сделано

### 1. Среда разработки

Создан **единый контейнер разработки** на основе `python:3.13-slim` со всеми необходимыми сервисами:

- **PostgreSQL 17** (порт `5432`) — база данных
- **Redis 7** (порт `6379`) — кэш и сессии
- **Python 3.13** со всеми зависимостями
- **VS Code Server** (порт `8080`) — IDE в браузере
- **Supervisor** — управление процессами

**Запуск:**
```bash
docker compose up --build
Доступ:

VS Code Server: http://localhost:8080

PostgreSQL: localhost:5432 (логин/пароль: postgres / postgres)

Redis: localhost:6379
```

3. Модели данных
Созданы все ключевые модели:

global_users — глобальные пользователи

tenants_layers — слои учёта (тенанты)

membership — членство пользователей в слоях с ролями и хешем доступа

common_dictionaries — универсальный справочник для общих данных

alembic_version — управление миграциями


4. Аутентификация и RBAC
Реализована трёхуровневая авторизация:

Роль	Описание
Суперадминистратор (super_admin)	Управляет пользователями системы, не имеет доступа к слоям
Руководитель (chief)	Создаёт компании (слои), управляет пользователями внутри слоёв
Пользователь (user)	Работает внутри слоя (с ограничениями)
Вход по связке:

Логин + пароль (проверяется по слоям)

Один пользователь может иметь доступ к нескольким слоям с разными паролями

Используется JWT и Argon2 для хеширования паролей

5. Веб-интерфейс
Разработаны страницы:

Главная страница со статусом системы

Страница логина

Страница смены пароля (с принудительной сменой стандартного пароля)

Управление пользователями (для суперадминистратора)

Универсальные справочники (единицы измерения, валюты, страны, регионы, города):

CRUD-операции

Поиск, сортировка, пагинация

Используемые технологии:

FastAPI — бэкенд

Jinja2 — шаблонизация

HTMX + Alpine.js — динамические обновления и интерактивность

Минимальный CSS — собственная стилизация

6. База данных и миграции
Включён Row-Level Security (RLS) для всех таблиц с tenant_id

Настроены политики изоляции данных на уровне PostgreSQL

Автоматическое применение миграций при старте приложения через alembic upgrade head

База данных создана с локалью C.UTF-8 для корректной работы с кириллицей

🔑 Логины и пароли по умолчанию
```
Пользователь	Логин	Пароль	Роль
Суперадминистратор	super_admin	admin123	SUPER_ADMIN
Руководитель (глобальный доступ)	chief	chief123	CHIEF
PostgreSQL	postgres	postgres	—
```
⚠️ Важно: При первом входе система принудительно предлагает сменить стандартный пароль.

📖 Как это работает (кратко)
1. Запуск контейнера
bash
docker compose up --build
поднимает все сервисы и применяет миграции.

2. Первый вход
Автоматически создаются два пользователя:

super_admin / admin123 (суперадминистратор)

chief / chief123 (руководитель)

3. Смена пароля
При первом входе система принудительно предлагает сменить стандартный пароль.

4. Управление пользователями
Суперадминистратор может создавать, редактировать и удалять пользователей (через интерфейс /admin/users).

5. Создание компании (слоя)
Руководитель (chief) входит с глобальным паролем chief123 и создаёт компанию через интерфейс /tenant/create, задавая пароль для доступа к ней.

6. Вход в компанию
Руководитель входит в созданную компанию с паролем, который он задал при создании.
